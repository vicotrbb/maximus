# Maximus implementation plan

> **For agentic workers:** Use superpowers:executing-plans for implementation and a fresh final reviewer. Track actual evidence in docs/progress.md.

**Goal:** Implement the entire supplied Linux Rust HTTP framework specification as Maximus.
**Architecture:** Local runtime and socket ownership per worker; existing Rust protocol engines; static handler dispatch and bounded streaming. Twelve focused crates match the requested structure.
**Tech Stack:** Rust 2024, Compio, Hyper, Rustls, h3, procedural macros.
**Spec:** docs/original-spec.md and docs/superpowers/specs/2026-10-15-maximus-design.md.

## Global constraints

- No undefined behavior or undocumented unsafe invariants.
- No unbounded request queues or uncontrolled memory growth.
- No optimization is accepted without measurable improvement and regression coverage.
- Mandatory unit, integration, concurrency, fuzz, and stress tests.
- All nonessential capabilities must be feature-gated.
- Preserve every requested capability. Evidence limitations are not implementation success.

## Review focus

- Ambiguous HTTP framing, encoded path separators, duplicate singleton headers: reject safely.
- Slow peers and stalled response consumers: bounded memory, timeouts and cancellation.
- Worker failure or partial bind failure: return startup error and clean up all listeners.
- Shutdown during TLS, body streaming or multiplexed requests: drain to a deadline.
- Feature combinations and protocol parity: no silently missing routes, limits or middleware.
